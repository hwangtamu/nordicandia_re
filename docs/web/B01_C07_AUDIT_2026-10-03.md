## 阻塞完成验收的问题

### F01 · P1 · C01 属性在真实战斗中丢失

位置：`CombatInstance.cs:282` 的 `ApplyRatings`、`:302` 的 `PlayerStats`。
`CharacterRatings.Apply` 已生成 `Conversion/Penetration/ArmorPenetration/DodgeChance/BlockChance/AlwaysHits/IgnoresCrits/DeadlyStrikeChance/HitChanceBonus` 等值，
但实例既不保存这些字段，重建 `CombatantStats` 时也未传入。

探针将转换=1、火穿透=.5、破甲=.75、闪避/格挡/致命打击=1、必中/暴击免疫=true 注入实例；
实际结算取用的 `PlayerStats` 对应值全部变为 **0/false**。
普攻、主动技能和怪物攻击均使用这条路径。纯 `ResolveBundleAttack` 测试绕开实例，未能发现。

验收要求：属性引擎 → 实例 → 实际命中端到端覆盖，包含装备/被动更换后的重新计算。

### F02 · P1 · C07 精通数据变化不等于实际效果变化

位置：`CombatRegistry.cs:529`、`:536`；`CombatInstance.cs:1426`。

* `EffectivePowers` 更新 Values/Multiplier/Cooldown/Radius/ManaCost，未同步通用 BuffBonus/BuffSeconds；
  Might 的 ImprovedMight 将 `Strength_Bonus_Percent` 从 **.75 改为 .78**，但实际 offense buff 仍为 **.75**。
* 所有 Operator 最后都按加法写回。运行时目录实际有 **46 个 Subtract、1 个 Multiply**，与 C07 文档的“全是 Add”不符。
  `MasteryMightPiercingStrength` 对 `Base_Cooldown` 的 Multiply=0 被当作加 0；探针显示冷却仍为 **30 秒**。
  当前 `Math.Max(1, cooldown)` 也需要按原版零冷却语义复核。
* **173/297 个精通的 Specs 为空**。这不证明原版精通无效果；当前 EffectivePowers 无对应行为处理，必须恢复实现类/触发逻辑。
* C07 的前置测试只检查 Map 数据存在，未实际发送“缺前置分配”命令。

验收要求：为数值型与行为型精通分别建立入口，覆盖乘法/条件/叠加、同技能多个精通组合及实际伤害/Buff结果。

### F05 · P1 · C02 的毒比较遗漏原版 override，换图清理也未贯通

位置：`BuffManager.cs:59`、`CombatInstance.cs:1064`、`:1164`。

网页所有 Buff 都按“剩余时长 → 层数”比较。
但本地基线中 `DebuffPoisoned.IsStrongerThan` @ **0x02B2F7A0** 有专用 override：
读取 `Tick_Damage_Per_Second`（静态偏移 `0x2378`），在非零 TimeoutDuration 分支进行除法，
比较结果非零时直接返回，之后才可能走基类。
本次从实际 ELF 复核了 `0x02B2F994`、`0x02B2FAC4` 的 `fdiv` 和后续比较分支。
不能只用基类反汇编得出“新毒因剩余时长更长，必定替换旧毒”。完整比较方向/调用约定应重新恢复后实现。

另外 C02 文档用来证明 DistinctComparer 的 **0x02B2583C 实际为构造函数**；
其 Equals 在 `0x02B2C3B4` 转发虚调用，现有证据不足以证明 DefinitionId|Source 的唯一键语义。

换图探针：施放毒云/召唤骷髅后调用 SetWorld，仍保留 **1 个 cloud / 3 个 minion**。
SetWorld 仅重建怪物和地图流程，未清理新效果实体及玩家临时 Buff。

验收要求：恢复各 Buff override 与去重调用链；在真实死亡/换图入口验证移除，而不只测试容器 Clear 方法。

## B04/B05 测试结果的正确解释

回放有价值，但样本的 `对照通过` 标签需要区分来源：

* 有些是根据反汇编公式计算的数值样本，可证明该公式的实现。
* poison_dot 只算 `PoisonHitDamageFactor * hitDamage`，不覆盖实际 Buff 替换或 tick 生命周期。
* deterministic_replay 是同一纯函数同种子调用两次，不是经 API 重复提交同一命令。
* relogin_blessing_roundtrip 是 Dictionary 的 JSON 序列化/反序列化，不是服务重启/重新登录流程。
* 三个 projectile 样本验证网页中的局部约束，没有原版录像输入或时间轴。
* FidelityReport 输出 actual，但未输出 expected；不读取样本的 status 来区分实机/公式/推断证据。

不能以 51/51 推导“51 个主动技能原版对照完成”。现有测试并未发现本报告列出的运行时断点。
